# Revisión SEO después del lanzamiento de EmDash

Fecha: 3 de octubre de 2026. Dominio: https://cursodeglobosonline.com/.

## Resultado y alcance

Se revisaron Search Console, el grafo de enlaces público, los metadatos, las relaciones editoriales, el proceso de publicación de EmDash y oportunidades de contenido. Se publicaron dos guías originales con imágenes propias y se corrigieron incidencias de importación y publicación. El resultado no equivale a garantizar posicionamiento, indexación ni ausencia futura de canibalización. La velocidad visual móvil sigue requiriendo trabajo.

## Search Console y canibalización

Los datos finalizados del 3 al 30 de septiembre muestran **261 clics, 12.509 impresiones, CTR 2,09 % y posición media 8,40**. El periodo anterior, 6 de agosto a 2 de septiembre, tuvo 173 clics y 2.755 impresiones. Estos periodos preceden al lanzamiento de EmDash: **no atribuir su crecimiento a esta migración**. El CTR menor, por sí solo, no demuestra una pérdida: cambió la mezcla y el volumen de impresiones.

Además del informe del conector, se consultaron 963 filas consulta/página, 1.900 filas segmentadas por país/dispositivo y 397 filas diarias de consultas seleccionadas. Search Console omite consultas anonimizadas; el análisis no representa todas las búsquedas posibles. [Evidencia agregada](../migration/verification/seo-followup-gsc.json).

Hay **ocho consultas donde aparece más de un artículo**. La mayoría de las páginas secundarias tienen una sola impresión. Por ejemplo, «cuantos globos lleva un arco» muestra seis impresiones de la guía de arcos y una de columnas. No existe evidencia suficiente para fusionar, redirigir o desindexar esos artículos.

En búsquedas comerciales como «curso de globos» y «curso de globoflexia» sí aparecen varias páginas de país y ciudad, incluso dentro de un mismo país/dispositivo. Eso merece seguimiento, pero no prueba perjuicio: las intenciones local y nacional son distintas y las páginas locales ya reciben clics. Se conservan. No crear más artículos informativos cuyo objetivo principal sea la misma consulta comercial de una ficha.

Se cruzaron con sugerencias y contenido ya existente. No se multiplicaron artículos sobre temas que la web ya resuelve. [Datos del proveedor](../editorial/2026-10-03/keyword-evidence.json).

## Correcciones adaptadas a EmDash

- El plugin de integridad exige palabra clave principal y rechaza una coincidencia exacta normalizada con otro blog publicado/programado del mismo idioma. Se verificó con un borrador privado: publicación rechazada con HTTP 422; borrador retirado a la papelera. No es detección semántica ni una restricción transaccional ante publicaciones simultáneas.
- Evita palabras clave principales que empiezan por «curso(s)» y H1 dentro del cuerpo. Los borradores pueden permanecer incompletos.
- Las rutas de sitemap inexistentes responden 404 en lugar de 200 con XML vacío.
- Se activó la caché nativa de objetos de EmDash, aislada por ambiente. TTL 60 s; revalidación 1 s; invalidación nativa al editar y referencias incluidas. Vista previa y modo edición la omiten. KV puede tardar alrededor de un minuto en propagar cambios; no se cachean HTML completos, votos ni comentarios.
- Se corrigió el importador GFM: los límites de una celda incluían las barras del Markdown. Ahora usa las posiciones del contenido interno y conserva negritas, enlaces y barras escapadas. La reparación del CMS utiliza revisiones nativas, respaldo previo y comprobación de que no haya un borrador editorial pendiente; no ejecuta el seed.

## Rendimiento: mejora parcial, pendiente real

Las peticiones HTTP desde el equipo de auditoría muestran, una vez calentada la caché, medianas de **1,114 s en inicio, 0,954 s en Colombia, 0,708 s en blog y 0,727 s en la guía del perrito**. La primera petición de inicio llegó a 6,585 s. Son muestras de respuesta HTTP desde un único equipo; no son Core Web Vitals ni percentiles de usuarios reales.

La segunda prueba móvil de Ubersuggest/PageSpeed sigue siendo mala: **LCP 11,7 s, FCP 2,7 s y TBT 298 ms**; la anterior había mostrado LCP 7,7 s. Las pruebas sintéticas varían, y no se puede concluir que la caché haya resuelto la carga visual. El proveedor señala aproximadamente 391 KB de JavaScript no utilizado y redirecciones, pero no devuelve el inventario de scripts ni la cadena completa para atribuirlos con certeza. No se desactivó GTM ni se alteró la medición comercial sin identificar primero qué etiquetas sobran.

Siguiente prioridad técnica: traza completa de Lighthouse con URL inicial/final y elemento LCP, inventario del contenedor GTM, coste de etiquetas externas, carga de fuentes y tamaños responsivos de imágenes antiguas. El HTML inspeccionado no hidrata islas React innecesarias. Las categorías de campo devueltas como FAST no incluyen INP ni ventana/muestra suficiente para certificar aprobación de Core Web Vitals.

## Criterio de seguimiento

Revisar un periodo finalizado posterior al despliegue, por país y dispositivo. Para posibles conflictos, comparar consulta, URL dominante, clics, conversiones e intención antes de consolidar páginas. Un artículo nuevo debe resolver una necesidad distinta, no solo variar el título. Google decide el rastreo y la indexación; un acuse del sitemap o IndexNow no es una confirmación de indexación.

Referencias técnicas: [versiones localizadas y hreflang](https://developers.google.com/search/docs/specialty/international/localized-versions), [sitios multirregionales](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites), [sitemaps y lastmod](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap). Las fuentes técnicas de los tutoriales están enlazadas en cada artículo.
